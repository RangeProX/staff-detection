# Staff identification

Finds the staff member in a 3D video by detecting their name tag, working out which
person is wearing it, and tracking that person through the frames where the tag is not
visible. Outputs the frames a staff member is present in (Task 1) and their position in
each frame (Task 2).

The design, measured results and limitations are in the written report, submitted
separately. This file
covers running it.

**Results for the sample clip** are in [results/sample/](results/sample/):
`staff_positions.csv` is the answer to both tasks (the frames it lists are the frames a
staff member is present; `x`, `y` are their position), and `staff_events.csv` logs how
each identity was started, handed over and lost.

## Setup

Python 3.11.

```
pip install -r requirements.txt
```

`annotate` opens an OpenCV window, so use `opencv-python`, not `opencv-python-headless`.

The trained tag detector is included at `models/tag_v4.pt` and `TAG_WEIGHTS` in
`staffcam/config.py` already points at it. If you retrain, copy the new weights into
`models/` rather than pointing into `runs/`: Ultralytics renames those folders when you
retrain, which silently loads the wrong model.

The pretrained person detector (`yolo11n.pt`, and `yolo11m.pt` for `probe`/`sweep`)
downloads on first use.

### Input video

The sample video was provided by the assessors and is not included in this repository.
Place it at `videos/sample.mp4` to run the commands below.

## Running it

```
python run.py all      --video videos/sample.mp4     # people -> tags -> link
python run.py render   --video videos/sample.mp4     # annotated video
python run.py timeline --video videos/sample.mp4     # coverage plot + trajectory
```

`all` runs the three pipeline stages in order. Each can also be run alone (`people`,
`tags`, `link`) — useful because `link` is fast and takes no GPU, so you can re-run it
after changing a linking setting without redoing detection.

Everything is written to `outputs/<video name>/`, so a second video never overwrites the
first. No threshold is hardcoded to any particular clip.

## Outputs

| File | What it holds |
|---|---|
| `person_detections.csv` | Every person detection, with its tracker ID |
| `tag_raw.csv` | Every tag detection above `TAG_RAW_CONF` |
| `tag_hits.csv` | Tag detections successfully matched to a tracked person |
| `staff_positions.csv` | **The deliverable.** One row per staff identity per frame |
| `staff_events.csv` | Identity starts, handovers, losses and anomalies |
| `staff_annotated.mp4` | The video with boxes, coordinates and tag markers |
| `timeline.png` | Coverage over time by evidence type, plus the path |
| `previews/`, `sheet_*.jpg`, `probe_*.jpg` | Diagnostic images from `people`, `sheet` and `probe` |

Only the hand-annotated ground truth (`ground_truth.csv`, `holdout.csv`) is committed
under `outputs/sample/`, because `score` reads it from there. A frozen copy of the
final results is in `results/sample/`; everything else is regenerated by a run.

### `staff_positions.csv`

`frame`, `timestamp`, `staff_id`, `track_id`, the box (`x1 y1 x2 y2`), the box centre
(`cx`, `cy`), the tag position if one was detected (`tag_x`, `tag_y`, `tag_conf`),
`source`, `tier`, and:

- **`x`, `y`** — the reported position. The tag centre when a tag was detected in that
  frame, the box centre otherwise.

`source` records how each label was obtained, and `tier` groups those into two levels of
evidence:

| `source` | `tier` | Meaning |
|---|---|---|
| `tag_hit` | confirmed | A tag was detected on this box in this frame |
| `same_track` | confirmed | Same tracker ID, close in time to a tag hit |
| `track_unsupported` | inferred | Same tracker ID, but far from any tag hit |
| `track_before_tag` | inferred | Same tracker ID, before its first tag hit |
| `fill` | inferred | Followed onto another track after the tracker lost the ID |
| `interpolated` | inferred | Straight line across a short gap with no detection |

Report confirmed and inferred separately. The confirmed tier is tag-grounded; the
inferred tier rests on tracking continuity.

## Reading the console output

`link` prints one line per staff identity, the measured walking speed, and any
self-detected anomalies. On an unseen video these warnings are the only available check,
since there is no ground truth to score against.

- **`LOST after frame N`** — an identity ended. The line gives the distance to the
  nearest candidate track, so you can see whether it narrowly missed the gate or whether
  nothing was there at all.
- **`CHECK handover`** — an identity moved to a new tracker ID, landing further from the
  predicted position than expected. Worth eyeballing.
- **`JUMP`** — a labelled box moved faster than a person physically can. Usually means
  the label switched to someone else.
- **`note: staff A and B overlap in time`** — two identities were live at once. Correct
  only if two tagged people really were on screen.
- **`N track(s) reached MIN_HITS but too few distinct observations`** — a track collected
  enough tag hits but they were clustered too closely in time to count as independent.
  This guard working as intended.

If no staff is found at all, it prints why rather than lowering anything: the raw tag
count, the highest confidence seen, how many tags landed inside a person box, and the
most distinct observations collected on a single track. A high confidence with few hits
inside a box points at association; a low maximum confidence points at the tag detector
not recognising an unfamiliar tag or lighting.

## Configuration

All settings live in `staffcam/config.py`. `link` validates them on startup and names any
that are missing. The ones most likely to need changing on new footage:

| Setting | Purpose |
|---|---|
| `TAG_WEIGHTS` | Path to the trained tag detector |
| `CONF` | Minimum tag confidence to count as a hit |
| `MIN_HITS` | Distinct tag observations needed to confirm an identity |
| `MIN_GAP_SEC` | Hits closer together than this count as one observation |
| `PERSON_CONF`, `PERSON_IMGSZ` | Person detector sensitivity and input size |
| `TAG_STRIDE` | Run the tag detector on every Nth frame (1 = every frame) |

Linking thresholds are expressed in person-sizes and seconds rather than pixels and
frames, and walking speed is measured per video, so they carry across resolutions and
frame rates.

## Evaluation

Accuracy is measured against hand-clicked ground truth.

```
python run.py annotate --video videos/sample.mp4 --step 15
python run.py score    --video videos/sample.mp4
```

`annotate` steps through sampled frames: click the staff member and press Enter, `n` if
they are not in the frame, `s` to skip, `q` to quit. It saves as it goes and can be
resumed. Annotate without looking at the pipeline's output for those frames.

For a held-out set that never influenced any setting, use a disjoint sample and a
separate file:

```
python run.py annotate --video videos/sample.mp4 --step 30 --offset 7 --gt-name holdout
python run.py score    --video videos/sample.mp4 --gt-name holdout
```

Score the holdout once, after the configuration is frozen, and change nothing in response.

The holdout figures in the report cover the same frame range as the tuning set (from
frame 435 on; the opening stretch cannot be labelled, see Known limitations). To
reproduce them:

```
python run.py score --video videos/sample.mp4 --gt-name holdout --gt-from 435
```

Pick a step that is **not divisible by `TAG_STRIDE`**, otherwise the annotated frames will
all be ones the tag detector already samples and the set cannot measure anything that
depends on tag sampling.

`score` reports recall, the share of frames where the person detector had a box on the
staff at all (the ceiling for any linking rule), precision by source and tier,
wrong-person labels, and false alarms on frames where the staff was absent. `--gt-from`
and `--gt-to` restrict it to a frame range.

## Diagnostics

```
python run.py sheet --video videos/sample.mp4 --start 1100 --end 1200 --step 10
python run.py probe --video videos/sample.mp4 --weights yolo11m.pt --imgsz 1280 --conf 0.1
python run.py sweep --video videos/sample.mp4
```

- `sheet` — contact sheet of annotated frames over a range. The fastest way to check what
  the pipeline did somewhere specific.
- `probe` — try a person-detector setting on a few frames without tracking.
- `sweep` — on the frames where the current run has no box on the staff, try several
  zero-label detector settings (test-time augmentation, larger input, four-way rotation,
  a bigger model) and report which recovers them. Needs `ground_truth.csv`.

## Training the tag detector

The labels are in `dataset/labels/` (YOLO format; an empty file is a negative frame with
no visible tag). The images are not included because they are frames of the assessors'
video: `fN.jpg` is frame N of `videos/sample.mp4`. The labelling tools that wrote both
are in `tools/`:

```
python tools/label_tags.py       # label every 6th frame: l = tag, n = no tag
python tools/label_range.py      # densely label a frame range
python tools/count_labels.py     # positives / negatives per split
python tools/train_tags.py       # fine-tune YOLO11n -> runs/detect/tag_v4
```

Training curves and metrics for the final detector are in `training/tag_v4/`.
`training/tag_v3/` holds the metrics of an earlier detector run.

## Layout

```
run.py                 CLI entry point
staffcam/
  config.py            all settings and output paths
  video.py             video helpers
  people.py            stage 1: person detection + tracking; also `probe` and `sweep`
  tags.py              stage 2: tag detection
  link.py              stage 3: association, confirmation, propagation
  viz.py               annotated video, timeline plot, contact sheets
  evaluate.py          ground-truth annotation and scoring
models/tag_v4.pt       trained tag detector
dataset/               tag training labels (images not included, see above)
results/sample/        final results for the sample clip
outputs/<video>/       generated output (only the ground truth is committed)
training/              training metrics and curves
tools/                 labelling, training and frame-viewing scripts
archive/               the abandoned template-matching approach (see report)
```

## Known limitations

Covered in full in the report. The ones that affect operation:

- The person detector misses the staff in roughly a third of the frames where they are
  visible, which bounds recall. This is the overhead viewing angle, not model size.
- The opening stretch of the sample clip has no confirmed tag and almost no person
  detections, so it cannot be labelled at all.
- A tag is assigned to the smallest person box containing it, which can pick the wrong
  person when someone walking overlaps someone seated.
- One tagged person usually produces several identities, because the tracker fragments
  them. Merging would need appearance re-identification.
